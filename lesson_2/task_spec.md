# Делим счёт — Task Specification

## Критерии приёмки

- Пользователь может ввести итоговую сумму чека и количество людей.
- После отправки формы отображается сумма, которую должен заплатить один человек.
- Расчёт выполняется как `итоговая сумма / количество людей`.
- Результат отображается с точностью до двух знаков после разделителя.
- Невалидные значения не приводят к расчёту: сумма должна быть положительным числом, количество людей — положительным целым числом.
- Для невалидных значений отображается понятное сообщение об ошибке.
- Предыдущий корректный результат не выдаётся за результат нового невалидного ввода.
- Интерфейс работает без аккаунта, сервера, базы данных и сетевых запросов.
- Страница корректно работает на desktop и mobile, доступна с клавиатуры и не требует внешних ресурсов.
- Итоговый артефакт соответствует ограничениям проекта и содержит только согласованные изменения.

## Goal - что и зачем

Создать простую страницу «делим счёт», на которой компания вводит итог чека и число людей, а каждый получает рассчитанную равную долю.

Цель — дать быстрый одноразовый расчёт без регистрации, сохранения данных и функций, не относящихся к базовому делению счёта.

## Workflow - порядок работы

1. Зафиксировать UX формы: поля для `Total bill` и `Number of people`, кнопку расчёта и область результата.
2. Определить правила ввода: итоговая сумма — положительное число, количество людей — положительное целое число.
3. Определить правило форматирования результата: равная доля одного человека с двумя знаками после разделителя.
4. Создать семантическую разметку формы, подписей, сообщений об ошибках и результата.
5. Описать адаптивные стили формы, focus-состояния, состояния ошибки и результата.
6. Реализовать локальную клиентскую валидацию и расчёт без сервера и сетевых запросов.
7. Обновлять результат при каждом новом корректном расчёте и блокировать результат при ошибке.
8. Проверить основной сценарий, граничные значения, доступность и мобильное отображение.
9. Зафиксировать рабочий результат в артефакте проекта.

## План проверки

### Основной сценарий

- Ввести сумму `100` и количество людей `4`: отображается `25.00` на человека.
- Ввести сумму с дробной частью и проверить корректность вычисления.
- Изменить значения и выполнить новый расчёт: результат обновляется.
- Повторно открыть страницу: данные не восстанавливаются из истории или аккаунта.

### Валидация и граничные случаи

- Пустая сумма и пустое количество людей отклоняются.
- Нулевая и отрицательная сумма отклоняются.
- Ноль, отрицательное, дробное или нечисловое количество людей отклоняется.
- Невалидный ввод не показывает новый расчёт и не приводит к `NaN` или `Infinity`.
- Сумма, которая не делится без остатка, отображается с двумя знаками после разделителя.
- Сообщение об ошибке понятно пользователю и связано с соответствующим полем.

### Технические проверки

- Проверить работу страницы как статического сайта.
- Проверить desktop и узкий mobile viewport без горизонтальной прокрутки.
- Проверить управление с клавиатуры и видимое focus-состояние.
- Убедиться, что нет сетевых запросов, внешних библиотек и внешних шрифтов.
- Убедиться, что в консоли браузера нет ошибок JavaScript.
- Убедиться, что не добавлены файлы и функции вне согласованного scope.

## Scope / Non-goals / Affected area

### Scope

- Одностраничная форма для ввода общей суммы чека.
- Поле количества людей.
- Равное деление суммы между всеми участниками.
- Отображение рассчитанной суммы на одного человека.
- Клиентская валидация и сообщения об ошибках.
- Форматирование результата до двух знаков после разделителя.
- Адаптивная и базово доступная вёрстка.

### Non-goals

- Аккаунты, регистрация, авторизация и профили.
- История чеков, сохранение расчётов и синхронизация между устройствами.
- Деление по отдельным позициям или распределение позиций между людьми.
- Разные доли, чаевые, налоги, скидки и конвертация валют.
- Назначение сумм конкретным людям.
- Бэкенд, база данных, аналитика, экспорт и сетевые запросы.
- Функции, не описанные в этой спецификации.

### Affected area

- `lesson_2/task_spec.md` — спецификация задачи.
- Файлы будущей реализации страницы в `lesson_2/`, если они будут созданы отдельной задачей.

## Constraints - как нельзя

- Нельзя добавлять аккаунты, историю чеков или деление по позициям.
- Нельзя сохранять введённые данные и результаты между сессиями.
- Нельзя отправлять данные на сервер или использовать сетевые запросы.
- Нельзя использовать npm, сборщики, фреймворки, бэкенд и внешние библиотеки.
- Нельзя подключать CDN, внешние шрифты и другие внешние ресурсы.
- Нельзя считать ноль, отрицательные значения или дробное количество людей допустимым.
- Нельзя показывать результат для невалидного ввода.
- Нельзя допускать отображение `NaN`, `Infinity` или пустого некорректного результата.
- Нельзя добавлять неоговорённые файлы без явного запроса.
- Нельзя изменять задачу CLAWD Wisdom в `lesson_1`.

## Current / Desired - язык фактов

### Current

- Нужна отдельная задача для страницы равного деления счёта.
- Пользователь должен вводить итоговую сумму чека и число людей.
- Требуется показать сумму для каждого человека.
- Аккаунты, история чеков и деление по позициям исключены.
- Реализация страницы ещё не определена в рамках `lesson_2`.

### Desired

- В `lesson_2` есть готовая спецификация страницы «делим счёт».
- Страница принимает положительную сумму и положительное целое количество людей.
- После корректного ввода показывает равную долю одного человека.
- При ошибке показывает понятное сообщение и не выполняет расчёт.
- Результат форматируется до двух знаков после разделителя.
- Данные не сохраняются, а расчёт выполняется локально.
- Задача CLAWD Wisdom в `lesson_1` остаётся неизменной.

- Результат — сумма, которую видит каждый человек при равном делении.
- Аккаунты делать не нужно.
- Историю чеков делать не нужно.
- Деление по позициям делать не нужно.
- Спецификация должна пройти через восемь вопросов: что меняем, зачем меняем, где меняем, scope, non-goals, ограничения, проверка результата и выходной артефакт.

- Зафиксирован план проверки основного сценария, ошибок, границ, доступности и мобильного экрана.
