# Делим счёт — правила проекта

## Назначение

Одностраничный статический калькулятор для равного деления счёта между участниками компании. Пользователь вводит итоговую сумму и количество людей, после чего получает сумму, которую должен заплатить один человек.

Расчёт выполняется локально по формуле:

```text
сумма на человека = итоговая сумма / количество людей
```

Проект не использует аккаунты, сервер, базу данных, историю расчётов или сетевые запросы.

## Состав проекта

```text
index.html       — HTML-структура страницы, форма, поля и область результата
styles.css       — визуальное оформление, layout, адаптивность и focus-состояния
js/script.js     — валидация, расчёт и обновление результата
                    
practiceAvailable/ — дополнительные практические задания и их локальные материалы
```

Перед изменением структуры сначала проверить фактический список файлов в папке. Не считать дополнительные материалы частью основной реализации без прямой необходимости.

## Функциональные требования

- Поле `Total bill` принимает положительную сумму.
- Поле `Number of people` принимает положительное целое число.
- Кнопка формы запускает локальный расчёт.
- Результат отображает равную долю одного человека с двумя знаками после разделителя.
- При пустом или невалидном вводе показывается понятная ошибка.
- Невалидный ввод не должен отображать новый результат и не должен приводить к `NaN` или `Infinity`.
- Каждый новый корректный расчёт заменяет предыдущий результат.
- Данные и результаты не сохраняются после перезагрузки страницы.
- Интерфейс должен работать на desktop и mobile и быть доступным с клавиатуры.

## Ограничения

- Использовать только чистые HTML, CSS и JavaScript.
- Не добавлять npm, сборщики, фреймворки, внешние библиотеки, бэкенд или базу данных.
- Не подключать CDN, внешние шрифты и другие внешние ресурсы.
- Не выполнять сетевые запросы и не отправлять введённые пользователем данные наружу.
- Не добавлять аккаунты, авторизацию, историю чеков, чаевые, налоги, скидки, разные доли или деление по отдельным позициям.
- Новые файлы создавать только по прямому запросу или если они явно нужны для согласованного практического задания.
- Сохранять существующие относительные пути между HTML, CSS и JavaScript.
- Не использовать inline-скрипты и inline-стили.

## Правила работы

1. Перед изменением прочитать относящиеся к задаче файлы и проверить текущую структуру.
2. Вносить минимальные изменения, необходимые для запроса.
3. Не менять проект `lesson_1` и не смешивать его логику с калькулятором из `lesson_2`.
4. Сохранять семантическую разметку, доступные подписи полей и видимые focus-состояния.
5. Проверять ввод до вычисления: сумма должна быть конечным положительным числом, количество людей — конечным положительным целым числом.
6. Не скрывать ошибку невалидного ввода за старым корректным результатом.
7. Не сохранять секреты, токены, ключи, персональные данные или локальные машинные пути в коде и документации.
8. Не передавать конфиденциальные данные в URL, логи, сообщения об ошибках или внешние сервисы.
9. Если требования противоречат друг другу или для реализации не хватает решения, обозначить это до изменения кода.

## Проверка результата

После изменения:

- проверить diff и убедиться, что изменены только ожидаемые файлы;
- открыть страницу через `file://` или простой статический сервер;
- проверить основной сценарий: сумма `100`, `4` человека → `25,00` на человека;
- проверить дробную сумму и округление до двух знаков;
- проверить пустые, нулевые, отрицательные, нечисловые и дробные значения количества людей;
- убедиться, что при ошибке не появляются `NaN`, `Infinity` или старый результат вместо сообщения об ошибке;
- проверить повторный расчёт и начальное состояние страницы;
- проверить keyboard-навигацию, видимый focus и работу на узком экране без горизонтальной прокрутки;
- проверить отсутствие сетевых запросов, внешних ресурсов и ошибок в консоли браузера;
- явно сообщить о пропущенных проверках и неустранённых ошибках.

## Критерий готовности

Задача считается выполненной, когда страница локально принимает корректные данные, рассчитывает равную сумму на человека, корректно обрабатывает ошибки и границы, работает на desktop/mobile и не выходит за согласованный scope.
