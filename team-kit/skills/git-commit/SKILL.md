# Git-коммит

Создавай ровно один Git-коммит из текущего рабочего дерева. Не выполняй push.

## Порядок действий

1. До добавления файлов в индекс изучи репозиторий и все текущие изменения:
   - Выполни `git status --short --branch`.
   - Проверь уже добавленные в индекс изменения с помощью `git diff --cached`, а изменения отслеживаемых файлов вне индекса — с помощью `git diff`.
   - Изучи неотслеживаемые файлы, показанные в статусе; прочитай те, которые могут войти в коммит.
   - Выполни `git diff --check` и `git diff --cached --check`, чтобы выявить проблемы с пробелами.
2. Сгруппируй изменённые файлы по назначению изменений. Выбери один логически связанный набор для коммита; не объединяй несвязанные изменения только ради того, чтобы включить все файлы. Если есть несколько отдельных групп, выбери наиболее очевидную и оставь остальные без изменений. Если суть изменений непонятна или нельзя выбрать подходящую группу, спроси пользователя до создания коммита.
3. Составь краткое сообщение в формате Conventional Commits:
   - `type(scope): повелительное описание` — если уместна область изменений; иначе `type: повелительное описание`.
   - Выбери подходящий тип, например `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `ci`, `perf` или `chore`.
   - Точно опиши выбранные изменения; не приписывай коммиту изменения, которых нет в выбранных файлах.
4. Добавь в индекс только выбранные файлы, указывая пути явно (при необходимости заключай их в кавычки). Не используй `git add .` или `git add -A`.
5. Создай ровно один коммит для выбранных файлов. Используй `git commit --only -m "<сообщение>" -- <выбранные пути>`, чтобы в коммит не попали несвязанные изменения, уже добавленные в индекс. Не удаляй из индекса, не сбрасывай, не отбрасывай и иным образом не изменяй остальные изменения пользователя. Если коммит не удался (в том числе из-за хука), сообщи об ошибке и остановись; не повторяй команду в обход хуков.
6. Проверь результат командами `git show -1 --format='%H%n%s' --name-only` и `git status --short`. Сообщи:
   - hash коммита;
   - точное сообщение коммита;
   - пути включённых в коммит файлов.

## Ограничения

- Никогда не выполняй `git push`.
- Никогда не используй `--amend` или `--no-verify`.
- За один запуск создавай не более одного коммита.
- Не включай в коммит несвязанные или не изученные файлы.
